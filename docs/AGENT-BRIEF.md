# External website agent: five rules

**44-2.de decision:** retain the existing OnPath WordPress drafts unpublished as reference. Do not delete or publish them and do not keep two public sites in sync. At the owner-approved launch, `onpath.earth` becomes the canonical site; redirects from any existing public paths are a separate owner action. This PR does not modify WordPress.

1. **Where code goes.** Only `happychriss/onpath.earth`. Work on a feature branch, open a PR and leave merging to the owner. Never write website code to `happychriss/OnPath`. Plain HTML/CSS/JS and the small Python static builder are sufficient. English lives at `/`, German at `/de/`, with corresponding language switches. The owner connects Cloudflare Pages to this repo; merging can deploy automatically after that connection exists.

2. **What you must not receive or commit.** No Cloudflare API tokens, WordPress passwords, app keys, credential files or broad access to the app repository. Request write access only to this website repo. Never copy private marketing research, numerical pricing proposals, internal plans, tester lists, private Drive IDs/links or archived source bundles into the repo. Only owner-approved public feature status and funding principles belong in website copy.

3. **Brand and technology.** Original logo: green square `#1F6E43`, white mountain and yellow path `#FFC94D`. Paths come from the app's `app/src/main/res/drawable/ic_launcher_foreground.xml`; website SVG is `assets/brand.svg`. Dark green `#174f31`, pale green `#e7f0e9`, Manrope font served locally. Yellow is a restrained waymark, not a dominant background. Keep the calm outdoor/editorial design, readable text, real photography, keyboard focus and responsive layouts. No framework or analytics needed. If analytics is proposed later, review actual processing and disclosures before adding it; “no cookies” alone is not a legal approval.

4. **Content and wording.** Bike and hike equally; ADFC members and local ride leaders are the first outreach audience. German uses normal adult “du”, concrete everyday benefits and short sentences. Avoid jargon, condescension, superlatives, competitor attacks and invented proof. Explain offline preparation, editing while recording, GPX in plain terms, and the complete place flow: OnPath search → place details → Google Maps for information → back to OnPath as a stop/destination; Google Maps → Share → OnPath works in the other direction. Core functions remain free, code is open and users control their tour files. Future paid extras should cover costs, development work and a donation, without claiming charity status or inventing prices/shares. AI-assisted development belongs mainly in the founder story, with respect for Komoot and no unsupported speed/quality comparisons. Keep browser planning, QR transfer, pairing and browser storage visibly marked as future work until confirmed. Never imply an ADFC or Google partnership. Include help for all core functions.

5. **Legal pages and launch.** Maintain `/legal/`, `/privacy/`, `/de/impressum/` and `/de/datenschutz/`, plus credits. The legal drafts must be completed for the real operator and hosting before public launch. Do not guess addresses, email, tax/registration IDs, legal bases or retention periods. Explain app and website processing separately, including map requests, Photon online search, Google Maps and diagnostics. Preserve asset licences. No payment terms, checkout, tracking or consent widgets until their actual need and implementation have been reviewed. Default builds remain noindex review versions. Only the owner approves launch and merges.
